Got Questions - chat mockups

Local knowledge base, no AI model. Drawer on desktop, full-height sheet on mobile. Colours are the real Dawn patrol and Night swell tokens; fonts fall back to system fonts here (the site uses Barlow). Text in the answers is taken from the real knowledge base entries 3.1 and 8.5.

  • Every control is at least 44px tall; the send button is 48px. The privacy line sits above the input as visible text, not a placeholder.
  • Answers are cards that never take focus; the input keeps focus. New answers are announced politely (aria-live).
  • Follow-ups are one-tap chips, so people never need to type a clever question.

6. Getting back to the chat from the Bible (decision needed)

Tapping a key verse in an answer opens that verse in the Bible reader. Today there is no way back except the browser's Back button, and Back lands on a closed panel. The return control must appear only when the visitor arrived from the chat; someone reading the Bible on their own sees nothing extra.

  • How it knows (all options): tapping a verse in the chat sets a flag in sessionStorage for this tab (never a URL parameter, so a shared Bible link never shows a button to a chat the recipient never opened). A visitor who opens the Bible from the menu in a new tab has no flag and sees no control.
  • Coming back (all options): the thread is already kept in the tab, so returning reopens the chat panel automatically with the conversation and scroll position as they left it. The flag is cleared when they return or dismiss it.
  • The browser Back button keeps working and also reopens the panel, because the panel remembers it was open.

UX decisions in one place

  • Drawer on desktop, sheet on mobile: the same pattern as the Bible picker; a dialog with a focus trap, Esc to close, focus returns to the button.
  • Short answer first, depth on request: a phone shows the whole short answer without scrolling; "Read more" reveals the explanation.
  • Chips over typing: related questions, terms and "tell me more" are one tap, and they send entry ids so they always work.
  • Honest labelling: "reviewed knowledge base, not a pastor". It never says AI.
  • Privacy rule visible: a line above the input and a clear inline error, not a placeholder or a colour change alone.
  • Safety: crisis replies are fixed text with tappable numbers; contested topics carry a badge and a note.
  • Control: Clear chat deletes the thread (kept only in this tab). Nothing is stored on the server.
  • Accessibility: 44px targets, visible labels, 4.5:1 text contrast in both schemes, aria-live="polite" on new answers, reduced-motion respected, keyboard operable throughout.
