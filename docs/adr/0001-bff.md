# 0001. Backend-for-frontend (BFF)

Status: accepted

## Context
The site needs forms that store personal and sensitive data. Exposing the FastAPI service directly to browsers adds CORS, public tokens and a larger attack surface.

## Decision
The browser only talks to Next.js. Server Actions and Route Handlers call FastAPI server-side with `Authorization: Bearer <SERVICE_TOKEN>` and the real client IP in `X-Client-IP`. Vercel overwrites `X-Forwarded-For` and `X-Real-IP` between the two projects with the web function's address (measured on a preview deployment), so the API trusts `X-Client-IP` only after the service token check. FastAPI rejects any non-health request without a valid token and still validates everything as if public. In production the API project is covered by Vercel Deployment Protection; only the web project (bypass secret) and Vercel Cron can reach it.

## Consequences
- No CORS on the public surface; API URL and tokens never reach the browser.
- One place for session cookies in Phase 2.
- Extra hop per request, and the service token must be rotated per the runbook.
- Public read-only endpoints may be exposed directly later; that needs its own ADR.
